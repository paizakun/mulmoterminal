# 共有アプリの 3 つの入口を、ページの下ではなくツールバーで繋ぐ

**状態**: 実装済み（mulmoserver、2026-08-16）。§5 の 1–6 すべて。実装で 5 点ずれた（§6）
**日付**: 2026-08-16
**実装先**: ほぼ全部 `../mulmoserver`。MulmoTerminal 側の変更は無い見込み
**前提**: [`docs/shared-app-principles.md`](../docs/shared-app-principles.md)、
[`plans/feat-shared-app-preview.md`](./feat-shared-app-preview.md)（入口 3 つの表と P4c）

この計画が答える問い:

> **`/a/` `/m/` `/p/` は同じアプリの 3 つの顔なのに、行き来はページ下端の
> 灰色の小さな 2 リンクだけで、しかも片方向しかない。
> 訪問者は、いま自分が何にサインインしていて、どこへ行けるのかを、どこで知るのか。**

## 1. 現状（読んだもの、行番号つき）

### 1a. リンクは片方向で、置き方が最弱

| 向き | 実装 | 場所 |
|---|---|---|
| `/a/` → `/m/` | あり（無条件） | `src/views/PublicApp.vue:75` |
| `/a/` → `/p/` | あり（無条件） | `src/views/PublicApp.vue:76` |
| `/m/` → `/a/`、`/p/` → `/a/` | **無し** | — |
| `/m/` ↔ `/p/` | **無し** | — |
| サインイン後の遷移規則 | **未実装**（設計だけある） | `feat-shared-app-preview.md:403`（P4c） |

`/a/` の 2 本は最下部・`text-xs text-gray-400`・スタッフ用と横並びで同格
（`PublicApp.vue:70`）。実際に押す人数が桁違いに多い participant 側が、
フッターの注記と同じ重みで置かれている。

### 1b. 文言が動作を名乗っていて、サインイン済みに嘘をつく

`src/i18n/en.ts:32-33` / `ja.ts:32-33`:

- en: `staffEntrance: "Staff sign-in"` / `participantEntrance: "Already booked? Sign in"`
- ja: `"スタッフの方はこちら"` / `"予約済みの方はこちら"`

**英語だけが動作（sign in）を名乗り、日本語は行き先を指している。** リンクは
無条件描画なので、サインイン済みの人にも "Sign in" と出る。これは誤り。

重要なのは、`PublicApp.vue:70` のコメントが正当化しているのは**ロールで分岐しないこと**
（名簿を読むことになる）であって、**サインイン状態で分岐しないこと**ではない点。
`uid` は同じテンプレート内で既に使われていて（`:19`, `:41`）、Firebase Auth の
状態はクライアントに元からある＝名簿を 1 バイトも読まない。

### 1c. ツールバーは既に出ている。それが**ホスト運用者のもの**であることが根本問題

`/a/` `/m/` `/p/` は全部 `Layout` の子（`router/index.ts:176-186`）なので、
`components/Toolbar.vue` が**すでに毎ページ描かれている**。つまりこの計画は
「ツールバーを足す」ではなく「そこに出ているツールバーが、来た人のものではない」
という話である。いま出ているもの:

- **サインアウト時**: nav は空（`v-if="isSignedIn"`）、右端に `account_circle` だけ
- **サインイン時**: `/` へ行くホスト接続アイコン（cloud / cloud_done / cloud_sync）。
  `hostId` があれば terminals / collections / issues / feeds のセクション nav まで出る

予約しに来ただけの他人が、サインインした瞬間に**ホストを選べと言われる**。
アプリ名はどこにも出ない。そして `/a/` の保証（内部語彙を見せない）は
「ページの中身」については守られているが、その上の帯が破っている。

### 1d. サインアウトはアプリから叩き出す

`Layout.vue` の watcher が、サインアウトを検出すると `clearHostId()` して
`router.push("/")`。`meta.staysOnSignIn` は**サインインしか見ていない**
（`composables/useGoogleSignIn.ts:21`）。`/a/{slug}` でサインアウトした人は、
名前を持たない URL を失ってホスト選択画面に立たされる。**これは 1b と同じ穴の
反対側**であり、サインイン側を直したときに一緒に直さないと非対称が残る。

## 2. 設計

### D-A. 共有アプリのルートは、別のシェルを描く

`Toolbar.vue` に条件を足すのではなく、**ルートの meta が「どちらのシェルか」を宣言する**。
`staysOnSignIn` と `tier` が既にそこにあるのと同じ理由 —「このページが上に載っている
人に何をするか」はルータに置く、という既存の権限配置に合わせる。

```
meta: { shell: "app", staysOnSignIn: true }   // a/:slug, m/:slug*, p/:slug*
```

`Layout.vue` は `shell === "app"` なら `AppShellToolbar` を、そうでなければ
今の `Toolbar` を描く。ホストの語彙（cloud、terminals、collections）は
共有アプリのページに**一切出さない**。オーナーが自分のアプリの公開ページを見に来た
ときも出さない — そのときの彼は訪問者であり、ホストの道具は他の全ルートにある。

### D-B. ツールバーが持つもの（左からアプリ名、右にメニュー）

| 位置 | 出すもの | 出さない理由 / 条件 |
|---|---|---|
| 左 | **アプリ名**（読めたときだけ） | 読めないときは**空**。名前を出すと「その slug は取られている」を漏らす（原則 5・`MemberApp.vue:15` の「unknown-app と not-on-roster は同じ文」） |
| 右 | **アカウント状態** — サインイン済みならアカウントのアバター／頭文字、未サインインなら `account_circle` | サインイン状態はクライアントに元からある。名簿は読まない |
| 右 | **ハンバーガー**（`MenuPopover` を再利用） | 中身は D-C |

**アプリ名の出どころは、ページが渡す。** ツールバーが自分で `apps/{aid}` を読みに
行ってはいけない — 読みが 2 本になり、失敗の仕方が 2 通りになり、`/m/` では
「読めない＝名前が無い」という 1b と同じ判定をツールバーが独立にやり直すことになる。
`usePublicApp` / `useMemberApp` が解決した名前を provide/inject（または 1 個の
reactive な current-app ストア）でシェルに渡し、アンマウントで**必ず消す**。
消し忘れると、次に開いた別アプリの帯に前のアプリ名が残る。

### D-C. ハンバーガーの中身

```
  <アプリ名>                     ← 帯に出ているものの再掲はしない
  ─────────────
  申込み・公開ページ    → /a/{slug}
  自分の予約           → /p/{slug}
  スタッフ             → /m/{slug}
  ─────────────
  <アカウント表示>  サインイン / サインアウト
```

- **3 本とも行き先の名前で書く。動作（サインイン）を名乗らせない。** 1b の直し方は
  「英語を日本語に合わせる」であって、状態で文言を差し替えることではない。
  ただし `/a/` で**未サインインのとき**だけ、`/p/` の行に補助文
  （"サインインが要ります"）を添えるのは可 — これは Auth 状態であって名簿ではない。
- **`/a/` では 3 本を無条件に出す**（現行の不変条件をそのまま持ち上げる）。
- **`/m/` `/p/` では条件付きでよい**: そこは既にサインイン済みで、
  roster tier / member tier の config が読めるかどうかで fail closed に判定できる
  （`feat-shared-app-preview.md:403` の「持ち物があるときだけ」と同じ規則）。
  出しても押せない行を作らないためだが、**判定のために新しい読みを足さない**
  こと。ページが既に読んだもので決まらないなら、無条件に出して押した先で
  断られるほうがまし。
- **これが `/m/` `/p/` → `/a/` の戻り道になる**（現状の空白）。「戻る」ではなく
  行き先を名乗るのは、`/a/` が誰にとっても意味のあるページだから — スタッフに
  とっては「客が見ている画面」、participant にとっては「もう一度申し込む」。

### D-D. サインアウトはアプリの上に留まる

`Layout.vue` の `push("/")` を、**shell が "app" のときは `/a/{slug}` へ**（＝
サインアウトしても描ける唯一のページ）に変える。`/a/` にいたならその場に留まる。
`staysOnSignIn` の対称形なので、meta の名前も見直す価値がある（`appScoped` など）。

### D-E. 足したら、下から消す

- `PublicApp.vue:69-77` のフッター 2 リンクは**削除**する。ツールバーと二重になる。
- `PublicApp.vue:3` の `<h1>`（アプリ名）も削除。名前は帯にある。
- `MemberApp.vue:3` の `PageHeader` の `title` は、アプリ名ではなく**いま開いている
  ビュー／テーブルの名前**にする。帯がアプリ、ページ見出しがその中のどこ、になる。
- P4c の「送信完了後に『自分の予約を見る →』」は**残す**。これはナビゲーションでは
  なく、いま起きたことに続く一手であり、帯のメニューでは代わりにならない。

## 3. 壊してはいけないもの（この変更が触る不変条件）

1. **`/a/` はサインアウトで無条件に描ける**（原則 1・D7）。帯もそう。アプリ名が
   読めなければ名前無しで描く。読めるかどうかで**ページの構造を変えない**。
2. **名簿を読んで表示を決めない。** Auth 状態（クライアント）とロール（Firestore）
   は別物。前者での分岐は自由、後者は `/a/` では禁止。
3. **「そんなアプリは無い」と「あなたは名簿にいない」は 1 文のまま**
   （`MemberApp.vue:15`）。帯のアプリ名は、この 2 つを見分けさせる新しい経路に
   なりうる。だから「読めたときだけ」ではなく「**このページが既に本文を描けている
   ときだけ**」名前を出す、と実装で縛るほうが安全。
4. **読みを増やさない**（原則 10 の隣接: 経路を通る全アプリが払う）。帯は
   ページが解決済みのものだけを使う。

## 6. 実装で設計からずれた 5 点（2026-08-16）

1. **名前が読めないとき、帯は「空」ではなく URL 名を出す**（D-B は「空」と書いていた）。
   slug は訪問者のアドレスバーに既にあるので、echo しても誰にも何も教えない。空の帯は
   ただ壊れて見える。**アプリの本当の名前は、ページが解決できたときだけ**という肝心の
   条件は変わっていない（`useAppShellTitle.ts` の `shellTitle.value || slug.value`）。
   副産物として `/m/{slug}/records/{cid}`（アプリ名を持たないページ）も帯が埋まる。

2. **P4c の「サインイン後の遷移」は、ほぼ書かずに済んだ。** 設計表の 3 行のうち
   「戻るため → `/p/`」は、メニューから `/p/` に**直接行ける**ようになった時点で
   遷移規則ではなくナビゲーションになった（サインインは `/p/` の上で起きる）。
   「送信するため → 留まる」は `staysOnSignIn` が既にやっている。実装したのは
   **送信成功後の「あなたのページを見る →」だけ**で、これは導線ではなくいま起きたことの
   続きなので、帯ではなく緑の完了ボックスの中にある。

3. **サインアウトの行き先を、純粋関数として router に置いた**（`src/router/signOutLanding.ts`）。
   `Layout` に if を書くのではなく、`staysOnSignIn` と同じ場所・同じ理由。**今いる
   ページがそのまま行き先になる場合は push しない** — 同一パスへの push はルータが
   失敗として報告するので、`/a/` でサインアウトした人はただ留まる。
   既存テスト（`test_host_chooser.ts` の "Signing out …"）は `router.push("/")` を
   直接見ていたので、`signOutNavigation(route)` を見るように書き換えた。

4. **帯のサインイン／アウトの文言は `appShell` 自前**にした。既存の `menu.signin` は
   日本語が「ログイン」で、共有アプリ側の文言は全部「サインイン」。1 つのメニューの中で
   両方の語彙を使うことになるので、`appShell.signIn` / `appShell.signOut` を足した。
   サイト自身のツールバーは `menu.*` のままで、そこは触っていない。

5. **`useMemberApp` の `begin()` が `name` を消していなかった**のを直した。帯はルート
   遷移を跨いで生きているので、前のアプリの名前が次のアプリの見出しになりうる —
   さらに「そんなアプリは無い／名簿にいない」で終わった run の後にも名前が残り、
   §3-3 の不変条件を破る。設計では触れていなかった、実装して初めて出た穴。

**入口メニューの行は、どの入口でも 3 本とも無条件に出す**（D-C は `/m/` `/p/` では
条件付きでよいとしていた）。既に読んだもので他 tier の持ち物は分からず、そのために
読みを足さない、と決めた以上、条件は書けない。押した先が断るほうがよい。
